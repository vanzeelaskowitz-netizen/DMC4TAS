# 原版《鬼泣4》DX9 地址对照

适用 Steam 45700，build 21360，x86。下表均为首选 VA，基址为 `0x400000`。`[x]` 表示读取一个 32 位指针。P 为玩家，E 为敌人，M 为 sMediator，U 为 sUnit，R 为 sWorkRate，K 为 sKeyboard。偏移和地址均为十六进制。

**已验证**表示标题现场用 `PROCESS_QUERY_INFORMATION | PROCESS_VM_READ` 读回。**静态**表示在本构建的指令、导入或属性注册中找到对应物。**推断**指出尚待游戏行为确认的解释。战斗字段本轮都没有房间样本。现场对象身份通过虚表 `+10` 的 DTI getter 和 DTI `+4` 的类名核对。[标题对象](../logs/dx9-title.json) · [池与内存区间](../logs/dx9-runtime-extra.json) · [映像检验](../logs/dx9-validation.json) · [本地反编译](../dump/decomp_dx9/) · [函数清单](../tools/ghidra/functions_dx9.txt)

**静态**　Ghidra 将倍率函数 `4A6800` 反编译为只有 `return` 的 `void` 函数。该函数的 SSE 指令实际计算倍率，调用方 `4A6890` 直接使用 XMM0 中的结果。[倍率指令与调用方](../logs/dx9-workrate.json)

## 堆、快照与场景

**已验证**　`E559B4` 的注册计数为 11。表首 `[E47D50]` 是模块内的 MtDefaultAllocator；其后十个槽是 MtHeapAllocator，池总容量 **337 MiB**。每个描述符 DTI 大小为 `280`，虚表 `BFEAE4`。池基址在描述符 `+34`，容量在 `+0C`，名字指针在 `+10`。逐池查询得到独立的 `MEM_PRIVATE / MEM_COMMIT / PAGE_READWRITE` 区间，区间长度等于容量，描述符均在对应池外。[逐池地址、类型与页属性](../logs/dx9-runtime-extra.json)

- **静态**　`8AFB20` 按名称、容量建池，`8BB160` 注册描述符。`8BB6F8` 经 IAT `B850CC` 调用 `VirtualAlloc(NULL, 容量, MEM_COMMIT, PAGE_READWRITE)`。**推断**　十个申请均符合 SE 写监视过滤条件；首次申请时间、实际覆盖十池和脏页复原仍**未知**。原版应核对整张表，启动探测的首池槽可取 `C307A8`。
- **已验证**　标题快照候选还包括 `.data`（RVA `820000`，虚长 `292968`），十个池外描述符，sApp（`[E5527C]`，大小 `2588`）及 sDevil4Main（`[E5574C]`，大小 `103D0`）。两单例都在十池之外。**静态**　DTI `+18` 的低位在此构建以字节计；`8AE090` 的分配常量核对了 sDevil4Main。**未知**　标题未出现的池外战斗对象。
- **已验证**　`A=[E552C8]`；标题读到 `[A+382C]=aDevil4`、`[A+3830]=aTitle`、任务和房间槽 `+3834/3838` 均为零，U 的单位线上有 uTitle。**静态**　aGame/aMission/aRoom 复用后三槽，`aGame+6C` 是房间 ID；`M+E0` 注册为任务号。
- **静态**　SE `M+14C` 对应的过渡对象在 DX9 为 `[M+DC]`，`40BB43` 同时检查对象和 `+18` 的完成标志。`M+478/480` 分别注册 `mpNowLoading/mNowLoadingMode`。`room+31` 注册 `mPauseFlg`，另有 uPauseMenu DTI。**推断**　SDK 给出的 `aGame+1D1` 可作暂停旁证。**未知**　任务读盘、过场及失焦时各标志的先后次序；标题不具备这些样本。
